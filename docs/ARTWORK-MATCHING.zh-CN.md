# 动态封面自动匹配

独立 `artwork-provider-am` 使用公开 Apple 目录发现候选，随后核对指定专辑的真实曲目表。播放器的标题、艺人、专辑和时长共同决定匹配；动态封面是否存在不参与曲目或发行版本的选择。手动绑定和明确 Apple 链接保留各自的现有优先级。

## 字段与发行版本

- 标题、专辑保留中文版本、翻唱、伴奏、Live、Remix、Acoustic、Demo、Remaster、Deluxe、Anthology、重录、地区和卷号等词。专辑名只是另一专辑名的完整前缀，不能证明两者等价。
- `- Single`、`- EP`、`- The 6th Mini Album` 等有分隔符的发行类型后缀可兼容，组合后缀逐层处理。独立标题 `Single` 或 `The 4th Mini Album` 不被删为空。
- 专辑前缀兼容仅用于查询字段明确以 `…` 或 `...` 结尾的情况；完整目录名称不能被当成截断候选。
- 艺人字段可删除纯原生文字的括号别名，如 `MEOVV (미야오)`；此规则不用于标题或专辑。合作艺人 `feat./ft./featuring/with` 的标题解析与艺人信用集合使用一致规则。
- 简繁字符使用固定版本 OpenCC 字表的单一候选字符映射。多候选字符保持原样；不做短语转换或音译猜测。数据来源、修改方式和许可证见 `artwork-provider-am/third-party/opencc/`。
- 混合文字艺人别名仍需专辑锚定；同语言名字片段或多位合作艺人的 token 合集不作为别名依据。
- Explicit/Clean 标注不会被通用归一化删除。标注差异需目录的专辑级评级证据；已验证的 Explicit/Clean 双发行仍须评级互补、发行日和曲目数一致等现有条件。未知评级或多余候选保持歧义。
- 名称的比较键由字母数字构成，其余字符只作分词。两类名称例外，因为它们折叠后就不再是名字：不含任何字母数字的名称（Ed Sheeran《=》《÷》、David Bowie《★》等）保留符号本身，`=`、`÷`、`+`、`×`、`-`、`?` 各自成键，仅包裹整名的括号去掉（`（＝）` 即 `=`），单独一对括号仍是它自己的名字；以纯符号开头的名称保留首个符号词，所以 `÷ (Deluxe)` 是 `÷ deluxe`、`- (Deluxe)` 是 `- deluxe`、`= (Tour Edition)` 是 `= tour edition`，三者互不混淆。以字母数字开头的名称完全不变：`1989 (Deluxe)` 仍是 `1989 deluxe`，`A - Deluxe` 仍与 `A (Deluxe)` 同键。
- “字段是否填写”只看原始文本，不看折叠结果：本地专辑名、最近记录和专辑快照以原文是否为空判断，任何折叠都不能把已填写的名称变成“未填写”。
- 商店附加在名称上的标签（艺人原生文字别名、Explicit/Clean、合作艺人信用、外文译名括注、Single/EP 发行类型）是具名折叠，由每个比较按需声明并按序应用；比较不会在其声明之外删除任何文本。多张候选专辑的取舍只有一个入口：先按商店自身的 Explicit/Clean 等价（任意档位），再按宽松档的同名版本规则，没有证据就保留歧义。

## 匹配严格度与缓存

| 档位 | 精确标题时长差 | 精确标题且有专辑锚定的最大时长差 | 明确截断专辑名的最小前缀比例 |
| --- | --- | --- | --- |
| 严格 | 2 秒 | 8 秒 | 75% |
| 标准（默认） | 3 秒 | 12 秒 | 60% |
| 宽松 | 6 秒 | 20 秒 | 45% |

阈值变化不会删除录音或发行版本标签。设置用于下次查询，查询开始时取一份档位快照；候选过滤、专辑页复核、排序、诊断与缓存写入使用同一份档位。宽松档另外负责同名版本选择，见下文“同名的多个版本”。

AM 查询的成功和失败决策使用 `match-v9-1080`，键包含档位阈值（宽松档另含同名版本选择标记）、市场、完整语义字段、时长、URL、资源限制和专辑截断标记。不同档位不会复用旧档位的查询决策；匹配逻辑升级后也不复用旧决策。

外文译名括注可兼容，例如 `特别的人 (Special Person)`；`中文版`、`粵語版`、`重錄`、`現場` 等语言/录音标签不能被当作译名删除。网易云身份缓存使用 `netease-query-v4`，失败按 songId 与资源限制隔离，已验证视频继续按专辑共享（专辑视频键 `netease-album-native-v2`）。

原始专辑快照使用 `album-v4` 与 schema 3，保留评级、发行日、曲目数和被跳过的曲目数量；复用时重新按当前档位核对当前歌曲。宽松档的同名版本选择写入独立的 `album-edition-v2` 快照，只有宽松档在共享快照不适用时读取；严格/标准档只读共享快照，不会继承宽松档的选择。已确认专辑的不可变视频仍可跨歌曲和档位共享，避免重复下载。旧查询/专辑索引失效不删除用户手动绑定，也不要求清空全部视频缓存。

合格候选按精确专辑、精确标题、艺人信用与时长依次排序。基本字段完全相同的不同 Apple ID 在严格/标准档保持歧义；不因搜索顺序或某一候选有动态资源而猜选发行版本。

## 同名的多个版本

同一艺人、同名（忽略 Explicit/Clean 标注）的多张专辑都核对到当前歌曲时，例如 US 的 Lady Gaga《MAYHEM》14 首版 `1792666546` 与 17 首版 `1837310866`（两者动态封面不同）：

- 严格/标准档返回 AMBIGUOUS（专辑兜底为 `multiple_album_matches`，曲目搜索打平为 `multiple_catalog_matches`）。最近记录标为“多个版本”并计入“需处理”；点按该记录会用专辑名直接搜索 AM，列出各版本供手动绑定。
- 宽松档选一个：Explicit 优先，其次歌曲数多的版本，最后目录 ID 较小者。扩充版通常包含另一版全部歌曲，按歌曲数选择可让整张专辑（含扩充曲目，它们本就唯一匹配扩充版）保持同一封面。任一候选页面因网络或解析失败未读完时保持可重试，不做选择；名称或艺人不同的专辑在任何档位都不合并。

## 目录与页面失败

手动绑定与自动候选发现采用不同的市场规则。手动搜索按用户选定市场直接读取该市场的 Apple Music 网页专辑区：iTunes 专辑索引可能整张缺失某专辑，同时仍返回其他艺人的同名专辑（2026-10-13 US 搜索 `MAYHEM` 返回 25 张，其中 3 张恰好名为 “Mayhem”，没有 Lady Gaga），无法从其结果判断缺失。CN 只用网页，不能用 US iTunes 的结果代替本地市场；其他市场仅在网页为空或不可读时改用该市场 iTunes，网页不可读且 iTunes 无结果时报告错误，不显示为“无结果”。

自动匹配先按播放器专辑名搜索并复核专辑页；只有缺少专辑名或专辑身份未确认时，才补一次曲目搜索（主艺人 + 规范化曲名）。专辑已确认但无动态封面、网络/解析失败及歧义直接返回来源路由，不继续多轮歌曲搜索。启用且已登录的网易云并发准备候选，只有 AM 最终失败才下载其视频；歌曲匹配及缓存规则见 [网易云接入说明](ARTWORK-NETEASE-INTEGRATION.zh-CN.md)。

曲目搜索可能只返回当前歌曲的 Clean 版，而正确 Explicit 专辑只出现在其它歌曲结果中。对已具备专辑名的查询，可从这一次补充搜索的同专辑/艺人曲目中保留专辑 ID 和评级线索，再直接复核候选专辑，不重复搜索。线索不能替代当前歌曲的真实页面校验，也不能把其它歌曲的发行日/曲目数当成专辑等价证据；同一 ID 的评级证据冲突保持可重试。宽松档在这次曲目搜索打平于多张同名专辑时，也用同一批线索复核这些专辑页，再按同名版本规则选择。

CN 查询保留 US 目录发现候选的链路，专辑页先验证用户市场。仅 `upstream_not_found` 或 `web_schema_changed` 可尝试同一 Adam ID 的 US 页面。限流、权限拒绝、DNS/传输故障、请求截止和取消保持原错误，曲目表不匹配不触发市场回退。

专辑兜底最多逐个复核 6 个候选页面。多个确认候选按“同名的多个版本”处理；只在其余候选的完整曲目表已排除当前歌曲时接受唯一确认候选。页面失败或跳过了无法解析的曲目且没有找到当前歌曲时，该候选仍未确认。超过页面预算保持歧义，保留手动绑定入口。

Debug 诊断仅记录搜索轮次、数量、市场和控制字段，不写完整搜索词、曲名或艺人。`titleMatches` 包含录音/评级校验；`titleBodyMatches`、`ratingRejected`、`requestedRating` 分别帮助区分标题主体命中、评级拒绝和请求评级。Debug 开关仍默认关闭。

试听时播放器可能上报片段时长（例如 QQ 的 60 秒），与公开目录的完整版时长不同。自动匹配不伪造完整版时长或放宽到任意差值；可播放完整版，或由用户手动绑定确切专辑。

## 验证边界

`AmPlatformMatchingTest` 使用 2026-10-06 公开网易云、QQ 和 Apple 响应的字段裁剪样本，原始 URL 与响应哈希保存在测试资源中。覆盖 Rich Man、BURNING UP 重复发行、晴天、等你下课和普通版 Fortnight 对 Anthology 的拒绝。测试不访问网络。

`AmLooseEditionTest` 与 `AmSearchTest` 使用 2026-10-13 US 公开网页专辑区（`MAYHEM`）和两张《MAYHEM》专辑页的字段裁剪样本，覆盖三档对同名版本的处理、扩充曲目的唯一匹配、候选页未读完时不选择，以及 iTunes 缺失专辑时的手动搜索。

`AmNameIdentityTest` 以性质而非逐例断言比较键：已知不同的专辑（含 `=`、`÷ (Deluxe)`、`- (Deluxe)` 等符号名）两两不得同键；同一专辑的合法写法必须同键；“是否填写”只由原文决定；2026-10-06 平台样本中的全部专辑名折叠后都不为空；符号专辑的绑定查找与替换互不串扰。

2026-10-14 用户已在设备上确认 identity 测试包：US 手动搜索列出两张《MAYHEM》、本地专辑 `=` 绑定成功、符号专辑互不覆盖、自动匹配正常。

2026-10-14 用户已在设备上确认本地导入测试包（`artwork-provider-am-1.0.5-debug-local-import.apk`，sha256 `63bce4b0…`）：专辑名为空时导入按钮置灰；方形 1080 SDR H.264 视频走复制、显示"原始画质"；手机竖拍视频裁剪后方向正确；HDR 颜色正常；超 2 分钟提示正确；锁屏显示导入的封面，删除绑定后恢复自动匹配。

单元测试与 Debug 构建验证本地实现；当前设备的 MediaSession、网络市场可用性、缓存/档位切换和 SystemUI 显示仍需设备确认。
