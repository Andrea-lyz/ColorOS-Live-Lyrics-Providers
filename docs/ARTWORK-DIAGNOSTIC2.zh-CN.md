# 动态封面 diagnostic2：固定 1080 与媒体异常定位

## 输入证据

diagnostic1 设备反馈（OPPO PKJ110 / SDK 37 / CN）显示：

- 自动匹配：iTunes 歌曲候选为 0；网页专辑候选为 21，标题匹配为 0。
- 绑定请求两次选中同一组 1080 视频，前三个分别完成约 11 MB、14.5 MB、18.9 MB 下载，
  后续返回 `IllegalArgumentException`；没有首样本/重封装成功记录。
- 第四个候选的累计范围 21003141 bytes 超过 20971520 bytes 限制，实际是大小超限，
  原先被归类为 `unsupported_hls_layout` 并覆盖了前三个异常。

以上不能确定异常的具体 Android 调用，也不能证明源文件损坏。

## 改动

按用户要求，大卡、小卡共用一份原生 1080×1080 视频：

- Provider 在所有展示尺寸下仅选择 AVC SDR 1080×1080，同尺寸码率从低到高。
  保持原文件预算和最多 4 个候选限制；没有可用的原生 1080 时回退静态，不下载小尺寸，不转码放大。
- 查询/专辑资源索引移除展示尺寸，保留身份、市场、明确专辑和客户端资源限制。
  新索引版本隔离旧尺寸结果和失败缓存；旧视频清单/大卡索引中的 1080 文件需再次验证后复用。
- 按已确认市场、专辑 ID 和资源限制合并进行中的视频下载。等待者复核已完成的缓存，
  独立获取自己的资源租约；取消/超时不越界取消另一个请求，其他专辑可并行。
  并发等待者可复用本次失败结果，但 gate 不持久缓存失败或取消。
- 大小卡缓存与播放的协议、Bridge 请求/布局、播放器身份和 generation 不变。

异常诊断：

- 打开文件、轨道数量/格式、选择轨道、首样本时间/flags、muxer 创建/启动/写入/停止分别标记阶段。
- 异常 detail 记录阶段、异常类型及有界 cause/调用栈中的类名、方法名、行号，不记录异常消息、
  源文件名、原始 URL 或私人路径。与本地日志的请求编号和候选编号关联。
- 大小超限单列 `source_file_too_large`，后续超限候选不覆盖此前已下载视频的处理异常。
- 本版仅补充异常定位；`IllegalArgumentException` 根因及修复效果仍待设备反馈。

## 手机复现

1. 覆盖安装 diagnostic1；确认诊断版底部版本为 `1.0.1-diagnostic2`。
2. 诊断版来源启用，开启脱敏诊断；Bridge 来源保持“动态封面诊断版”。
3. 保留上次出错的手动绑定，先复现视频错误，不必再次清空绑定走自动匹配。
4. 进入锁屏，等待结果；能播放时再切换大小卡验证共用。然后导出 TXT 发回。
5. 日志中 `ARTWORK_AM_VARIANT_FAILED detail=stage=...` 将指出具体调用。
   已缓存成功的 1080 视频可直接复用；若要对照原始重封装，需在视频不使用时清除未使用缓存再复现。

诊断默认关闭。完成后关闭日志并按需要切回正式来源。诊断包不是正式修复发布或设备验收结论。
